Gaps — ordered by blast radius if left unaddressed

Critical — liability surface
No HEP
information_not_advice flag exists in code but there is no structured HEP payload, no tier 1/2/3 assignment, no SLA, no checkpoint. Blueprint: without this, the agent cannot defend its decisions under SOC2, EU AI Act, or NYC record-retention.
Critical — no guardrails
No Hooks
No PreToolUse submit-gate. No secrets-scrub. No idempotency ledger. Nothing prevents a future agent from double-filing a DOB form or leaking credentials in a tool call.
High — data integrity
No Idempotency
Double-filing a DOB alteration is expensive to unwind. Double-recording an ACRIS document is a legal event. The idempotency ledger (sha256 key → cached result) is cheap to build and load-bearing.
High — skill quality
Untested Skills
All 4 skills have been written but none have been run through the three-scenario test (happy path / edge case / stress). Production-grade requires passing all three.
High — output quality
Markdown Output
PathwayResult renders as plain text / markdown. For field use and client-facing output, HTML is significantly more readable and shareable. Thariq: nobody reads a 100-line markdown file.
Medium — infrastructure
Neo4j + Temporal
No property graph (BBL bitemporal ownership), no durable execution. Blocked on hardware provisioning. These are Day 6+ work — do not start until after Day 5 ship.

What the Blueprint explicitly says about skipping HEP

"A system that can autonomously file 60% of things and emit a structured, reviewable action card for the other 40% is vastly more valuable — and vastly more defensible under SOC2, EU AI Act retrospective oversight, and NYC record-retention requirements — than one that files 90% but cannot explain what it did."

The moswalk equivalent: every consult that touches a landmarked property, a rent-stabilized building, or an open ECB violation should emit a structured HEP payload — not just a information_not_advice: True flag. The payload becomes the audit trail and the licensed-professional handoff surface.

What the Blueprint says about skipping hooks

"Hooks enforce what prompts cannot." The submit-gate hook is non-negotiable for a domain where double-filing DOB or ACRIS has real legal consequences. It runs in a deterministic 60-second window and exits with a code that Claude Code treats as absolute — it cannot be argued out of by a clever prompt.

Maturation roadmap — dynamic, unbloated

Principle from all four sources: add mechanisms only when the gap causes real pain. Do not build the full Blueprint spec upfront. Layer in capabilities as needed.

The unbloat principle

From all sources: add a layer only when the absence causes real, named pain. The current architecture (CLAUDE.md + 4 Skills + 2 Rules + session_log + FieldAPI) handles single-device field consultation correctly. Hooks and HEP are the next two load-bearing additions because they protect against the failure modes that grow linearly with usage. Neo4j and Temporal are the two load-bearing additions after ship because they're required for multi-week regulated workflows. Everything else is optional.

Repeatable process for future intelligence influxes

You will receive more articles, PDFs, and research. Here is the repeatable three-step process built into the system as a skill:

Step 1 — Intake filter (always applied)

QuestionIf yesIf no
Does this change a sequencing or legal invariant?Immediate — update permit_pathways.yaml or rules/Continue to next question
Does this validate or invalidate a core architectural choice?Add to council brief + log decision in session_logContinue
Does this introduce a new mechanism moswalk doesn't have?Add to roadmap with priority and unbloat testContinue
Does this improve how we output, communicate, or explain?Queue for format/UX improvement (HTML, skill, etc.)Discard or archive
Is this noise (general AI hype, vendor marketing)?Discard—

Step 2 — Signal extraction format

SOURCE: [title + author]
SIGNAL: [one sentence — the core claim]
RELEVANT_TO: [which moswalk component(s)]
VERDICT: validated | gap | partial | discard
ACTION: [specific file to change, or "roadmap item #N", or "none"]
UNBLOAT_TEST: [does adding this require removing something to stay lean?]

Step 3 — Disposition

Validated signal
Log in session_log.py as decision(). No code change unless it reveals a test gap. Keeps the audit trail of architectural choices.
Gap signal
Add to ROADMAP.md with: priority, unbloat test (what does this replace or reduce?), blocker (what must exist first?). Do not build immediately.
Invariant change
Immediate edit to permit_pathways.yaml or .claude/rules/. Run tests. Commit. This is the highest-priority disposition — Local Laws change, agency sequences change.
Format/UX signal
Queue as a skill improvement or output format update. HTML rendering of PathwayResult is an example of this disposition from today's intake.
