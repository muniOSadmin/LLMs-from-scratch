What is this?

Three levels of explanation
🎒 High School Level — The Simple Version

Imagine you want to renovate a building in NYC. You need permits from the Department of Buildings, but also possibly from Landmarks (if it's historic), the EPA (if there's asbestos), and a dozen other city agencies — each with their own forms, timelines, and rules. moswalk is an AI assistant that runs entirely on your iPhone and knows all of these rules. It's like having a very smart consultant in your pocket — except it never connects to the internet and never shares your client data. It uses a small but powerful AI model (~1 billion parameters, compressed to fit on-device) and can talk to other computers on your home Wi-Fi to do harder thinking tasks.

🎓 College Level — The Technical Version

moswalk is a multi-agent inference system built around a custom 1.1B-parameter LLM (MoswalkLLM) with Grouped-Query Attention (GQA), Sliding Window Attention (SWA), SwiGLU FFN, and RoPE positional embeddings. The model is quantized to INT4 (group-wise PTQ) and exported to CoreML for the Apple Neural Engine. A Tailscale mesh connects four Apple devices; the inference coordinator on the iPhone orchestrates a layer-sharded pipeline across workers, with speculative decoding (draft k tokens → verify → accept/reject) for throughput gains. Deterministic grounding comes from a YAML agency registry (139 orgs), a Neo4j property graph keyed on NYC BBL, and live API feeds from DOB BIS, DOB NOW, PLUTO, and ACRIS.

💼 Founder Level — The Business Version

NYC has 1.1 million buildings, ~$150B in annual construction permits, and a regulatory maze spanning 139 active city agencies. Every project needs multiple agency sign-offs — the sequencing is non-trivial, costs are opaque, and mistakes are expensive. Existing tools (StreetEasy, DOB NOW, eCB portal) are siloed. moswalk's wedge is sovereign AI for field professionals — architects, expediters, developers — who can't risk client data in cloud tools and need answers in the field without Wi-Fi. The iPhone-first, mesh-compute model is a structural moat: no GPU cloud bills, no data liability, no downtime. The near-term risk is that the Llama 3.2 weight transplant (Day 1 of the sprint) is still unfinished — without real pretrained weights, the model is random noise.

Swarm Inference Topology

swarm_config.py · swarm_worker.py · swarm_coordinator.py
Mode A — Pipeline (2-4 devices)
The 24 transformer layers are split across N devices. Each device processes a contiguous slice and hands the hidden-state tensor to the next device. Good for: multi-device throughput.
📱 Coordinator (iPhone)
embed + layers 0–5 + lm_head + sample
↓ float16 activation (4 KB/token)
🖥️ Worker 1 (Mac Desktop)
layers 6–11
↓ float16 activation
💻 Worker 2 (Mac Air M1)
layers 12–23 → returns to coordinator
Mode B — Speculative Decoding (1-2 devices)
A small draft model proposes k=5 tokens quickly. A full verifier checks them all in one pass. Accepted tokens are free speedup; rejected ones fall back gracefully. Good for: single-device latency reduction.
📝 Draft
Coord runs layers 0–3 autoregressively × k=5
Produces: 5 candidate tokens + logits
→
✅ Verify
Full 24-layer model runs once on draft sequence
Produces: verify logits for each position
→
✓/✗ Accept
Ratio test p/q per token
Accept run + 1 bonus token
⚠ Sim only: The verify path calls self._all_blocks in-process. Real distributed verify (worker via TCP) is not wired up yet. This works for single-device testing but won't scale to the mesh without swarm_inference.py.
Mode C — Hybrid (4 devices) — defined, untested
Coordinator drafts speculatively (layers 0–3) while three pipeline workers act as the joint verifier. This combines both speedup strategies. Defined in swarm_config.py:hybrid_4_device() but no end-to-end test exists. The coordinator's _verify_draft() currently does not route through workers. NEEDS WIRING

Agency Registry Snapshot

agencies.yaml · 139 active orgs · OTI April 2026 · deterministic foundation
Why this matters (founder level)

The agency registry is the single most valuable deterministic asset in the system. It never hallucinates. It knows which agencies report to which Deputy Mayors, which require sequential sign-off, and which are quasi-judicial (BSA has no reports_to). All Python code must import from this YAML — never hardcode agency codes. The agency-codes.md and agency-sequencing.md rules enforce this at the session level.

Critical Review

Honest assessment — what needs development / pruning / pivoting / synthesizing
🔨 Needs Development
01
convert_llama.py — Day 1 debt, never done
Without real pretrained weights (Llama 3.2 1B), MoswalkLLM is an architecture sketch, not a model. Every downstream demo, perplexity eval, and CoreML export produces garbage. This is the highest-priority unblocked task in the entire project.
02
swarm_inference.py — missing entry point
There's no unified script that loads the model, picks a topology based on what devices are reachable on Tailscale, starts workers, and exposes a generate(prompt) API. Without it, the swarm components can't be used end-to-end.
03
Four skills — none implemented
agency_pattern_navigator, property_trigger_scanner, t3_discovery, premortem are named in the architecture but have zero code. These are described as "90% of the value." Build them before more model work.
04
BBL resolution + API connectors
DOB BIS, DOB NOW, PLUTO, ACRIS connectors are all undefined. Without BBL resolution, the property trigger scanner can't work, and the agency pattern navigator has no starting node.
✂️ Needs Pruning
01
MacBook Air 2014 — dead weight
The 2014 Intel machine runs no model and serves only as a BIS mirror. At 8 GB RAM and a 12-year-old CPU, it adds Tailscale maintenance overhead with zero inference value. A $5/month Backblaze backup replaces it entirely. Free up the mental load.
02
Hybrid mode — premature
hybrid_4_device() is defined and partially wired but has no test, no real verify routing through workers, and requires 4 simultaneous healthy devices. For a solo founder, this is a 3rd-order optimization. Ship pipeline + speculative first.
03
KV cache in SwarmWorker
SwarmWorker._kv_caches is allocated but never used — the _run_one_token call passes use_cache=True to the block, which has its own internal cache. The worker-level cache list is dead code. Remove it.
04
Phi-4 Mini on the sifting node
Firecrawl + Phi-4 Mini for web crawling is a reasonable future feature, but Day 4/5 depend entirely on iPhone + swarm working first. The sifting node adds no value until the core inference pipeline is stable. Defer to post-TestFlight.
↩️ Needs Pivoting
01
TcpTransport → MultipeerConnectivity (iOS blocker)
Raw TCP sockets are not App Store compatible on iOS. The Transport protocol is correctly abstracted for swapping, but the iOS shim must be written in Swift using MCSession. This should be the first thing built on Day 4 — before any SwiftUI.
02
Speculative verify path: in-process → distributed
_verify_draft() currently runs self._all_blocks locally. For single-device use this is fine, but it means the coordinator holds two copies of the model (draft + full) in RAM. On an 8 GB iPhone with a 550 MB INT4 model, this is manageable — but the architecture needs to acknowledge this explicitly and design the distributed verify path for the mesh case.
03
Solo founder GTM: field professionals before developers
The deepest technical moat (mesh swarm, ANE inference) is not what will drive the first 10 paying users. An expediter using moswalk in the field cares about: fast permit lookup, correct agency sequencing, and offline reliability. Prioritize the skill layer + UI over swarm sophistication.
⚡ Needs Synthesizing
01
agencies.yaml + Neo4j → single property graph query
The YAML registry and the Neo4j BBL graph are currently separate assets with no connector. They should be synthesized into a single query interface: bbl_to_agency_path(bbl) → [AgencyNode] with sequential_after edges already embedded. This would let skills query one thing instead of two.
02
Quantize → Export → Validate as one pipeline
Currently micro_quantize.py and micro_export.py are separate scripts. They should be a single build_model.py: load weights → quantize → measure perplexity → export CoreML → print Swift template. This removes manual steps and makes Day 5 hardening tractable.
03
SwarmCoordinator.generate() ↔ Skill dispatch
Right now generate(prompt_ids) takes raw token IDs. The skills layer needs a higher-level interface: consult(query: str, bbl: str) → ConsultResult that handles tokenization, skill routing, agency graph lookup, and confidence gating in one call. This is what swarm_inference.py should be.
04
Confidence scoring across model + deterministic layers
The agency-sequencing rule says confidence < 0.70 → surface stale flag. But confidence is never computed anywhere. It needs to synthesize: (a) model output probability, (b) date of last agency registry update, (c) known Local Law changes since last crawl. None of these are connected yet.
